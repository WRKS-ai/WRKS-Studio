# DESIGN — Global taste + system (the constitution)

Applies to every page generated by WRKS Studio. Overrides in per-page
blueprints only when explicitly noted. Extracted + refined from the
`~/.claude/global-memory/feedback_*` taste-profile files and the 2026
AI-tells research.

## Constitutional intent

**This document is law, not suggestion.** Every reference bundle in
`blueprints/` provides *inspiration*; DESIGN.md provides *rules*. When
inspiration conflicts with rules, rules win. The LLM has design
latitude within these rules — never outside them.

The goal: outputs that read as if a human designer built them.
Combinatorial variance from the reference corpus × voice_descriptor ×
brand palette. NEVER a generic AI-template look.

## Boundary: WRKS Studio chrome vs generated output

The WRKS Studio app itself (the dashboard, theater, panels) uses brand
purple, ambient glow effects, orb-family visuals — that's WRKS's own
brand identity. **These are BANNED in generated user sites.** A user
site inherits the user's brand palette applied under editorial
restraint. It never inherits WRKS's chrome vocabulary.

If it's a purple orb, a rotating gradient border, an aurora-background,
or a spotlight effect — it belongs to WRKS Studio (maybe), never to
the site we're building for Alex or Sarah.

## Reference corpus

Generation reads 1-2 reference bundles from `blueprints/references/`
(plus this DESIGN.md) and remixes them for the current user's brand.
The corpus at launch:

- `personal-brand/` — Bill-Fanter (creator, dark, bento-heavy)
- `references/wrks-online/` — SaaS/agency (dark, data-heavy, italic accents)
- `references/tomorrows-sunrise/` — Community/wellness (light warm, nature imagery, editorial)
- `references/claxton-law/` — Professional services (light clean, trust-signal heavy)

The corpus router (in the runner) picks 1-2 based on `voice_descriptor
+ business_type + site_intent`. Opus is told to *remix under this
constitution*, not to copy.

## Multi-page composition

**Every WRKS site is multi-page.** Single-page sites are the exception,
not the default. When a user submits a brief, we generate 3-5 pages
(Home + supporting pages per their business type), publish them under
one subdomain, and cross-link them via a shared nav.

**Page-type specs live in `blueprints/pages/`** — one MD per page type,
universal (not per-reference-bundle):

- `pages/about.md` — the who-we-are page
- `pages/services.md` — the what-we-offer page (also named /coaching,
  /practice-areas, /features per domain)
- `pages/contact.md` — the how-to-reach-us page
- `pages/lead-magnet.md` — the email-capture page (also named
  /newsletter, /guide, /watchlist per resource)

Home stays as the reference-bundle-defined composition (each bundle's
`sections.md` describes the home page).

### Business-type → pages default mapping

The runner generates these pages by default, per business_type:

| business_type | Pages generated |
|---|---|
| `personal_brand` (sells) | Home + About + Services + Contact (4) |
| `personal_brand` (builds audience) | Home + About + Lead-Magnet + Contact (4) |
| `service` (any professional service) | Home + About + Services + Contact (4) |
| `saas` | Home + About + Services + Contact (4) — Services page includes pricing tiers |
| `agency` | Home + About + Services + Contact (4) |
| `ecommerce` | Home + About + Contact (3) — product pages out of scope for launch |
| `other` | Home + About + Contact (3) |

Users can drop or add pages via the theater / dashboard (post-Ship-3
refinement UI).

### Cross-page consistency rules

When we generate multiple pages per site, several things MUST match
across every page:

1. **Nav** — identical structure, links, and CTA on every page. Only
   difference: the current page's nav item gets a visual current-state
   marker (thin underline in accent OR bolder weight — never a background
   pill). Nav links resolve to real routes (`/`, `/about`, `/services`,
   `/contact`), never `#anchors`.

2. **Footer** — identical on every page. Same brand mark, same nav
   columns, same copyright year, same social row. This is repetition
   as trust — visitors verify they're still on the same site.

3. **Palette + typography** — inherit from the same brand palette /
   type stack across pages. Never a "dark About page" if Home is
   light-cream.

4. **CTA vocabulary** — the primary CTA repeats across pages but with
   contextual variation: "Book a call" on Home + "Book a discovery
   call" on Services + "Send a message" on Contact. Never the same
   copy verbatim in 4 places (DESIGN.md ban: repeated CTAs).

5. **Voice tone** — one writer's voice through the site. If Home is
   first-person warm, About is not third-person corporate. If Home
   uses italics for accents (banned anyway), About doesn't.

6. **Copyright year** — always current year, always identical.

### Nav link naming

Nav labels reflect THIS business, not the generic SaaS template.

- Local service business (law, medical): `Home / About / Practice Areas / Contact`
- SaaS: `Home / Features / Pricing / About / Contact` (if 5 pages)
- Personal-brand creator: `Home / About / Coaching / Newsletter` (if 4 pages, no explicit Contact)
- Agency: `Home / Work / About / Contact`
- Ecommerce: `Home / About / Contact` (product pages linked from Home)

Never: `Home / Product / Features / Pricing / Blog / Login / Get Started`
across all sites. That's the AI-template default that reads as generic.

### Page-slug URLs

The subdomain is `{slug}.wrksstudio.com`. Additional pages live at:

- `/` → Home
- `/about` → About
- `/services` OR `/coaching` OR `/practice-areas` OR `/features` → Services
- `/contact` → Contact
- `/newsletter` OR `/watchlist` OR `/guide` → Lead-Magnet

The runner emits each page's HTML with the correct URL slug in nav
links. Middleware routes any `{slug}.wrksstudio.com/<path>` to the
correct stored page.

## Philosophy

Editorial magazine restraint. Aesop / Mercury / Linear / Stripe Press
territory. Not Notion-playful, not Wix-generic, not consulting-firm blue.
The site should feel like an art director laid it out, not an AI templated
it. Real over decorative. Restraint over ornament.

## Non-negotiable BANS

Reject any output containing these:

**Typography bans**
- Italics of any kind (no `italic` class, no `font-style: italic`, no
  italic-variant typefaces, no `<em>` / `<i>` for emphasis)
- Uppercase inside body copy (mono-caps only for eyebrow labels)
- Comic Sans, Papyrus, Impact, any script/handwriting except signature use
- Default `font-family: sans-serif` — always name a real typeface
- **Poppins** — dead giveaway of AI/no-budget templates
- **Inter or Geist used for ALL THREE roles** (display + body + mono) — signals a no-pairing-decision AI template. Pair different families across roles.
- Mono-caps eyebrow above every headline (Linear-cargo-cult) — use only when nav context is thin
- Gradient text on headlines (`bg-clip-text` violet→pink) — the universal AI-demo move
- Decorative italic accent word in a headline ("Build *beautiful* things")
- All hero clamps maxed to 96-120px — bigger ≠ premium; product-UI hero caps at 60px

**Color bans**
- Pure `#000000` and `#ffffff` at large fills (use `#0a0a0c` / `#f5f0e6`
  or the palette's neutrals)
- AI-signature purple → blue → teal gradients (rgba(139,92,246) → rgba(59,130,246))
- Neon oversaturated colors (`>85%` saturation on primary)
- More than one accent color visible per section
- Rainbow multi-color palettes; pick a hue family

**Layout bans**
- Centered heroes as the default (asymmetric editorial only)
- Three-column identical card grids without contrast in size or emphasis
- `h-screen` / `100vh` / `100dvh` — use fixed px `min-height`
- Boxed cards for EVERYTHING (pick form factor: sphere, arc, ribbon,
  hairline-divided rows — mix in cards where they earn it)
- Full-viewport hero images (bleed the right column, keep copy on left)
- **The default AI-wireframe sequence**: hero → 3-cards → testimonials → logo bar → CTA. Editorial rhythm required, not this default.
- **Generic bento** — 3-4 asymmetric tiles that don't carry unique content weight ("Linear clone" pattern)
- **Everything rounded `rounded-2xl`/`rounded-3xl`** — no material distinction between elements
- **Blanket `shadow-lg` on every card** — no elevation hierarchy
- **Same nav across every site**: `Product / Features / Pricing / Blog / Login / Get Started`. Nav should reflect THIS business, not the generic SaaS template
- **FAQ always 6 questions with the same 6 questions** ("How does it work? / Is it secure? / Can I cancel?") — vary count + questions per user context
- **Marquee logo bar looping infinitely** — especially with padded duplicates to look "trusted"
- **"As seen in" logo bar** with TechCrunch/Forbes/Wired unless the user actually was
- Excessive glassmorphism — one glass surface per page maximum (nav or one card, not both)

**Motion bans**
- `scale()` on hover greater than 1.02
- Bounce cubic-beziers on primary CTAs (linear-app style, ease-out only)
- Parallax on above-fold content (or on hero image, ever)
- Auto-play video with sound
- Infinite spinning icons / orbits
- **Rotating conic-gradient card border** (the "AI-glow border" — universal Aceternity/Magic-UI tell)
- **Aurora / meteor / spotlight backgrounds** — Aceternity stock hero backgrounds, instantly recognizable
- **Cursor-trailing sparkles / gradient follow** — outs v0/Bolt exports
- **Number-count-up on stats in viewport** — the "AI counter animation" pattern; show final numbers directly
- **Fade-up-on-scroll for EVERY element** — Framer Motion default; motion should have hierarchy, not blanket every child
- **Floating gradient orb / blob** in the hero background — Aceternity/Magic-UI signature
- **Glowing halo behind headline** (soft radial `blur-3xl` div behind text)
- **Blob decorations** — abstract organic SVGs behind content for space-filling

**Copy bans (write these NOWHERE)**
- **The AI verb pool**: Elevate, Unlock, Unleash, Empower, Seamless,
  Seamlessly, Revolutionary, Cutting-edge, Leverage, Next-gen,
  Game-changer, Ecosystem (as filler), Journey (as filler), Transform
  (as filler), Delve, Harness, Tapestry, Paradigm, Robust, Holistic,
  Streamline, Craft (verb overused)
- **"It's not [X], it's [Y]"** formulation — signature ChatGPT rhetorical move
- **Em-dash confetti** — no more than one em-dash per paragraph; ChatGPT scatters them like glitter
- **Three-benefit triads** with periods: "Fast. Beautiful. Yours."
- **"From X to Y in Z days/minutes"** headline template
- **"We don't just X — we Y"** antithesis pattern
- Curly-quote / straight-quote mixing (pick one style, keep consistent)
- "In today's fast-paced world"
- "We understand that…"
- Fabricated stats without attribution (no "increases conversions by 47%"
  unless the user's data literally says so)
- **Stat clusters "10x • 99.9% • 500+"** with dot separators and no source
- Emoji in headlines / CTAs / body copy
- Multi-claim headlines ("The best X for Y that also does Z") — one claim
- **"Get started free" repeated 5+ times on a single page** — vary primary CTAs
- **"Book a demo" duplicated in nav + hero + mid-page + footer** — pick 2 max

**Meta-cruft bans** (never render as decoration)
- "EST. 2026" pills
- Roman numerals as section labels ("N° 01 — INTRODUCTION")
- Decorative-only mono caps ("THE BRIEF", "OUR PROCESS" when there's no
  section they lead into)
- **Small circle/orb decorations anywhere** (before wordmarks, in hero
  bg, as feature-card accents — all banned in generated output)
- Section eyebrows on every headline (use only when nav context is thin)
- **"Powered by AI" / "AI-first" badges** in nav or footer — reads as apology
- **"Trusted by 10,000+ teams"** with no logos + no proof + no link
- **StyleGAN founder headshots** — never use AI-generated faces; if no real photo, use initials + subtle background
- **Faceless stock-avatar testimonials** with plausible-sounding "Sarah K., Product Manager" — testimonials need real names + real context or they're omitted
- **© year mismatch** — always use CURRENT year (2026); never hardcode 2024 (training-cutoff leak)

**Icon bans**
- **Sparkle icon (✨) = "AI feature"** — the shorthand of shame
- **Robot / brain / lightbulb / rocket** for "smart / launch" — Heroicons cliché
- **Duotone gradient-filled icon in rounded-square** — the "feature-card icon" pattern
- Emoji as icon substitute in feature cards (🚀 ⚡ ✨ 🎯)
- **Lucide 24px stroke-1.5** as the ONLY icon size/weight throughout — vary per hierarchy (16/20/24) or the fingerprint gives us away

## Required patterns

Ship every output with these:

**Typography stack (single family discipline)**
- Display: Fraunces (variable), Cabinet Grotesk, Instrument Serif, or
  Playfair (pick ONE per site based on voice_descriptor)
- Body: Geist Sans, Inter, Söhne, or Space Grotesk (pick ONE per site)
- Mono: Geist Mono, JetBrains Mono, IBM Plex Mono (for labels + code)
- Load via `<link rel="preload">` from Google Fonts
- Never use both a serif display AND a serif body

**Type scale (rem-based, must be present)**
- Display / h1: 60-80px (clamp 60-80), weight 500-600, tracking -0.03em, leading 1.04
- Section heading / h2: 36-48px, weight 500-600, tracking -0.02em, leading 1.1
- Card title / h3: 20-24px, weight 600, tracking -0.015em, leading 1.2
- Body: 16px (min), weight 400, tracking -0.003em, leading 1.6
- Lead / subhead: 18-19px, weight 400, leading 1.55
- Small / caption: 13.5px, weight 500
- Mono eyebrow: 11.5px, weight 500, tracking 0.14em, uppercase

**Color palette (5 tokens, all named)**
```
primary       #hex   — most visible accent, hero CTAs, key metrics
secondary     #hex   — dark ink for body text, section borders
tertiary      #hex   — quiet accent, quote treatment, decorative
neutral-warm  #hex   — cream/bone bg for light sections (never pure white)
neutral-dark  #hex   — near-black for dark sections (never pure black)
```
With scale ramps: 5 stops each `100/300/500/700/900` (light → dark).
Rules:
- ≤1 accent color visible per section
- Saturation ceiling 78% for primary, 32% for tertiary
- Palette source: HARD-CONSTRAINED to extracted brand palette when ingest
  provides one. Otherwise Opus picks per voice_descriptor.

**Button styling**
- Primary CTA on light: solid neutral-dark bg + neutral-warm ink, pill or
  10px radius, 14px vertical / 26px horizontal padding, 15px semibold
- Primary CTA on dark: solid `#ffffff` bg + neutral-dark ink (same
  dimensions)
- Secondary CTA: transparent + 1px border matching text color, no fill
- Hover: 1px `translateY(-1)`, no scale, brighten fill 4-8%, 200ms ease-out
- Active: `translateY(0)`, inset shadow, 60ms snap
- Radius options: 6px (sharp), 12px (default), 999px (pill) — pick one per
  site, use consistently

**Spacing scale (px, USE ONLY THESE VALUES)**
`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 88 / 100 / 120 / 168`
No other values. Ever.

**Layout tokens**
- Container max-width: 1180px (or 1440px for dense info sites)
- Container horizontal padding: 40px (24px on mobile <768px)
- Section vertical rhythm:
  - Light sections: 100px top / 100px bottom
  - Dark sections: 120px both (larger to breathe)
  - Hero: 168px top (clear floating nav) / 128px bottom, min-height 720px
- Grid base: 12 columns, 24px gutter

**Motion tokens**
- Enter: spring physics, stiffness 100, damping 20
- Hover: 200ms ease-out `[0.2, 0, 0, 1]`
- Layout shifts: 300ms cubic-bezier `[0.4, 0, 0.2, 1]`
- Only `transform` and `opacity` — never animate width/height/margin

## Motion vocabulary (voice-gated tiers)

Motion has hierarchy. Not every element animates. Tier 1 is always-on,
Tier 2 activates by voice, Tier 3 is one signature moment per site
(voice-gated).

**Tier 1 — Always on (CSS-only, zero JS overhead)**
- Hero content fade-up on load (opacity + 12px translateY, 500ms ease-out, 100ms stagger)
- Card hover lift (translateY -1px, shadow warmed, 200ms)
- Sticky nav backdrop-blur intensifies on scroll (backdrop-filter 8px → 20px)
- Button hover microstates (background, translateY, shadow warm)
- Link underline draw (text-decoration or ::after pseudo, 200ms)

**Tier 2 — Voice-gated (small vanilla JS via IntersectionObserver, ~2-8KB)**
Activates for: `bold`, `expert`, `playful`
- Scroll-triggered section fade-in (opacity + 8px translateY, once per section)
- Sticky nav shadow transition
- Testimonial carousel swiper
- Subtle 4-6px parallax on hero background image (never on above-fold copy)

Skip for: `warm`, `professional`, `quiet` — these voices read cleaner
with pure Tier 1 motion.

**Tier 3 — Signature moment (ONE per site, voice-gated)**
Activates only for: `bold`, `playful`
- ONE hero moment: subtle grain overlay, animated gradient shift on
  hero bg (2-color HSL shift over 12s), OR a text-mask reveal on the
  headline. Pick ONE.
- Never combines with other Tier 3 candidates.
- Never applied to `warm` / `professional` / `quiet` / `expert` voices.

**Motion intensity per voice (summary)**

| voice_descriptor | Tier 1 | Tier 2 | Tier 3 |
|---|---|---|---|
| bold | yes | yes | one moment allowed |
| playful | yes | yes | one moment allowed |
| expert | yes | yes | never |
| professional | yes | never | never |
| warm | yes | never | never |
| quiet | yes | never | never |

**Shadow recipes**
- Card resting: `0 1px 3px rgba(0,0,0,0.04), 0 20px 44px -20px rgba(0,0,0,0.12)`
- Card hover: same but `-16` blur (deeper)
- Elevated (modal, floating nav): `0 12px 34px rgba(0,0,0,0.35)` + inset
  `0 1px 0 rgba(255,255,255,0.9)` when on white
- Never pure `#000` shadows — always cool-tinted `rgba(20,30,60, x)` or
  neutral-dark-tinted

**Icon system**
- Stroke-only (1.7px stroke width, Feather / Lucide style) unless
  voice_descriptor is `playful` (then duotone)
- 16px / 20px / 24px sizes, no fractional
- Never emoji in place of icons

## Editorial composition rules

- **Asymmetric heroes**: copy left rail (60% width, max 780px) +
  portrait/hero-image right column (40%, full-bleed to edge). Never
  center-stack.
- **Section rhythm**: alternate light and dark sections. Long runs of
  same-tone sections lose the eye.
- **Whitespace as design**: 88-120px between sections. Cramped is
  cheaper-looking than sparse.
- **One focal element per section**: don't compete headlines with images.
  Either the headline is huge and image is quiet, or the image is hero
  and the headline is small caps.
- **Progressive disclosure**: state → context → action, not action → context → state.
- **Photography over illustration**: real photos beat illustrated icons
  every time. When illustrations are used, keep them monochromatic and
  strokey.

## Positive human-craft signals (aim for these)

The bans list is defensive. Here's what human-crafted sites actively
DO that AI templates don't:

- **Single typeface with real pairing intent** — display face + one
  workhorse; no third font. Typography is the last thing AI can't fake
  when done well.
- **Real photography** — commissioned or well-selected stock, not
  abstract UI mockups or StyleGAN faces. 78% of consumers detect
  generated imagery (2026 Getty VisualGPS).
- **Editorial asymmetry** — hairline eyebrows, ragged-right blocks,
  generous whitespace around one focal element (Aesop, Stripe Press,
  Linear, Mercury reference cluster).
- **Actual product screenshots** — real UI, real data, real cursor
  states — not Dribbble tiles or abstract shapes.
- **Purposeful motion** — one signature transition tied to a product
  truth, not fade-up-on-every-child.
- **Neutral palette + one earned accent** — restrained. Ink + cream +
  one warm or cool tone. Not gradient-washed.
- **Content that names things specifically** — real customer names
  with real photos, real numbers with sources, real dates.
- **Unusual layouts** — split-screen scroll, horizontal sections,
  sticky sidebars — anything that breaks the hero → 3-cards → CTA
  gospel.
- **Copy in one voice** — no antithesis, no verb-clusters, no em-dash
  confetti. A single writer's cadence throughout.
- **Craft in the details** — hover microstates, focus rings that match
  the accent, keyboard shortcuts documented, 404 page with personality.

The positive signal cluster to aim for: **Aesop / Linear / Mercury /
Stripe / Notion Calendar / Raycast / editorial print**. These sites
read as human because a designer *chose to remove* everything on the
AI-tells list — and left one deliberate move per hierarchy layer.

## Accessibility (baked in, non-optional)

- Every image: `alt=""` (empty for decorative) or descriptive alt
- Every button: text label (no icon-only buttons without `aria-label`)
- Color contrast: WCAG AA minimum (4.5:1 body, 3:1 large text)
- Focus states: 2px outline in `primary` with 2px offset
- Motion: respect `prefers-reduced-motion` (disable spring physics)
- Skip-to-content link at top of `<body>`
- Semantic HTML: `<header>`, `<main>`, `<section>`, `<nav>`, `<footer>`

## HTML output rules (for LLM generation)

- Emit ONE complete HTML document per page (doctype → html → head → body)
- `<head>`: meta charset, viewport, title, description, og:image, og:title,
  favicon, preconnect Google Fonts + font stylesheet link
- Tailwind CDN in `<head>` (`https://cdn.tailwindcss.com`) for
  self-contained rendering
- Inline `<style>` in `<head>` for CSS variables (palette + type),
  overrides Tailwind for design tokens
- No external JS bundle (small `<script>` for menu toggle etc. inline)
- Semantic HTML5 tags
- All Tailwind classes; no external CSS file needed
- Every editable element gets `data-edit-id="section.slot"` for future
  inline editing
